The pattern going forward
This is the Git workflow you'll use for every feature in this project:
main (stable, always working)
  └── feature/ollama-client     ← build here
  └── feature/fastapi-backend   ← Phase 2
  └── feature/pdf-parser        ← Phase 2
  └── feature/scaffold-generator ← Phase 3
Rule of thumb: one branch per feature, one commit per meaningful step. Don't wait until everything is perfect to commit — commit when something new works, even if small. Recruiters who look at your history will see real incremental progress, which is far more convincing than one giant commit.

fastapi — the web framework. You write Python functions, it turns them into HTTP endpoints. Much faster and cleaner than Flask.
uvicorn — the server that actually runs FastAPI. FastAPI is just the framework; uvicorn is what listens for incoming HTTP requests. Think of it like: FastAPI is the restaurant, uvicorn is the building it sits in.
pymupdf — reads PDF files and extracts their text content. Despite the name it has nothing to do with music — "mu" is the Greek letter μ, shorthand for micro.
python-multipart — allows FastAPI to receive file uploads. Without this, POST /upload-pdf would reject any file you send it. Also the imports
